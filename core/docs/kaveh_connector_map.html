The integration strategy — one principle
Kaveh speaks three universal interfaces: framework gateways, OpenTelemetry, and native SDK wrappers. Any connector that speaks one of these three gets full observability, auth, validation, and cost tracking — with zero changes to the agent code.
// The universal entry point — works for any agent, any language, any framework KAVEH_ENDPOINT=https://kaveh.yourdomain.com OPENAI_BASE_URL=$KAVEH_ENDPOINT/frameworks/claude-code/openai

The two connectors that give you everything else for free
MCP — the universal tool protocol
Every MCP server becomes a Kaveh-controlled tool automatically
// Any MCP server registered in Kaveh // gets full auth + audit + cost tracking kaveh mcp add --server https://gmail.mcp.server kaveh mcp add --server https://stripe.mcp.server // Kaveh discovers all tools, wraps them, // enforces policies before every call
MCP is becoming the standard tool protocol. If Kaveh wraps the MCP layer, every tool that becomes MCP-compatible is automatically a Kaveh connector. This is your connector multiplier — support MCP and you support hundreds of tools at once.
OpenTelemetry — the universal trace protocol
Any OTel-instrumented agent sends data to Kaveh with zero changes
// Any agent already using OTel // just points its exporter at Kaveh OTEL_EXPORTER_OTLP_ENDPOINT=https://kaveh.yourdomain.com // Kaveh accepts OTel traces, // enriches with cost data + policy violations, // surfaces in dashboard
OTel is the standard observability protocol. Being an OTel-compatible collector means any developer who already instruments their code sends data to Kaveh without a single SDK installation. Lowest friction onboarding path possible.
