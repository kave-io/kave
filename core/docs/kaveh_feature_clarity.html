The sharp boundary — what kaveh is not
Kaveh does NOT do this
✕Run agents or schedule their execution — that's OpenClaw/NemoClaw
✕Provide LLM APIs or model hosting — that's Ollama, OpenAI, Anthropic
✕Build prompt chains or workflows — that's LangChain, LangGraph
✕Store or index your business data — that's your RAG layer, your DB
✕Be a chatbot or AI assistant — it has no chat interface
✕Replace your auth system (Keycloak, Auth0) — it augments it for agents
✕Train or fine-tune models — not your business
Kaveh does exactly this
✓Intercepts every agent action and records what happened, why, and what it cost
✓Enforces what each agent is allowed to do before it does it
✓Validates that agent outputs match expected schemas before they hit your system
✓Tracks token spend per agent, per team, per task and alerts on anomalies
✓Gives you a dashboard to see all of the above across your entire org
✓Works with any agent framework, any LLM, any language via SDK or HTTP
One sentence definition
Kaveh is the control plane for AI agents — it doesn't run them, it watches them, controls them, validates them, and tells you what they cost.
Think: what Datadog is to servers, what Cloudflare is to HTTP requests, what Stripe Radar is to payments — Kaveh is to agent actions.
Feature breakdown — what it does and how
Module 1 Agent tracing & observability
Trace recording
Every LLM call, tool use, memory read/write, and agent decision is recorded as a structured trace with input, output, latency, model, and cost. Searchable, replayable.
Go SDK wraps LLM client. HTTP middleware for other langs.
Span linking
Multi-step agent runs are linked into a single trace tree — you see the full chain of what the agent did, not isolated calls. Like distributed tracing but for agent reasoning.
Trace ID propagation via context.Context in Go
Error & anomaly detection
Automatic detection of hallucination patterns, schema violations, infinite loops, and unexpected tool calls. Alerts via webhook, email, or Slack.
River background jobs, rule engine in Go
Replay & diff
Re-run any recorded trace against a new model or prompt version. See what changed. Essential for debugging regressions after model updates.
Stored trace → replay endpoint → diff view in dashboard
Module 2 Agent identity & access control
Agent identities
Each agent gets its own identity (not a shared API key). Kaveh issues ephemeral, scoped credentials per agent run — auto-expire after the task completes.
PASETO tokens with agent claims, short TTL
Tool-level permissions
Define exactly which tools each agent can call, with what parameters, under what conditions. "This agent can read files but never delete. This agent can send emails only to internal domains."
Casbin policy engine, evaluated at the enforcement layer
Credential vault
Agents never see real API keys. Kaveh holds the credentials and proxies the calls — the agent requests "use Stripe" and Kaveh injects the key, logs the action, and enforces limits.
Encrypted credential store in PG, proxy layer in Go
Full audit log
Immutable record of every action every agent took, who authorized it, what credential was used. Exportable for compliance (SOC2, GDPR).
Append-only table, ClickHouse for scale
Module 3 Output validation & guardrails
Schema validation
Define the expected output shape of any agent. Kaveh validates every response before it reaches your application. Bad output triggers retry, fallback, or alert — never silent corruption.
JSON Schema + custom validators in Go middleware
Retry & fallback policies
Configurable: retry with same model, retry with fallback model, escalate to human review, or return safe default. No more hardcoded retry logic in every codebase.
Policy config in YAML/dashboard, executed by SDK
Content guardrails
Block outputs containing PII, sensitive patterns, or off-topic content before they hit downstream systems. Configurable per agent, per environment.
Regex + lightweight classifier, runs in-process
Module 4 Token economics & cost control
Cost attribution
Every token spent is tagged to an agent, a task, a team, and a user. You know exactly who is spending what and on what. No more mystery AI bills.
Extracted from LLM response headers + SDK instrumentation
Budget enforcement
Set monthly/daily token budgets per agent, per team. When a budget is hit: warn, throttle, or hard-stop. Jensen's "token salary" vision made real and manageable.
River job checks budget counters, blocks at SDK enforcement
Model routing recommendations
Kaveh analyzes your traces and tells you "70% of this agent's calls could use Haiku instead of Sonnet with no quality drop — save $340/month." Actionable, not just data.
Offline analysis job, complexity scoring per trace
Spend dashboard
Real-time cost view across all agents, teams, and models. Trend lines, anomaly spikes, projected monthly spend. The AWS Cost Explorer for your AI stack.
ClickHouse aggregations → Nuxt 4 dashboard
How developers integrate — three paths
Go SDK — drop-in wrapper around any LLM client. Zero config to start, full control when needed.
import "github.com/kaveh-dev/sdk/go" — wraps OpenAI, Anthropic, Ollama clients. Context-aware, zero overhead.
HTTP proxy — point your LLM base URL at Kaveh. Works with any language, any framework, no SDK needed.
OPENAI_BASE_URL=https://your.kaveh.instance/proxy — one env var, full observability, no code changes.
OpenTelemetry exporter — emit traces in OTel format. Works if you already have OTel instrumentation.
Plugs into existing observability stacks. Meets teams where they are.
Compatible with everything — no lock-in
OpenAI Anthropic Ollama (local) Gemini OpenClaw LangChain LangGraph Any HTTP agent Go Python TypeScript REST API
