## The one-line version

Kave is a middleware framework for AI agents — the same way Express is middleware for HTTP requests, but instead of handling web traffic, Kave handles everything an agent does.

---

## The longer version

AI agents are replacing humans in software workflows. They call APIs, read databases, send emails, execute code, and make decisions — autonomously, at scale.

But the software those agents interact with was built for humans. It has no concept of "this request came from an agent with a $50/month budget, owned by a client who should only have access to their own data, and I need a full audit trail of everything it touched."

That's the gap Kave fills.

---

## The mental model

Think of Kave as a **Django or Rails, but for agents instead of humans**.

When a human uses a web app, the request passes through a middleware stack — authentication, authorization, validation, logging. Django packages all of that into a coherent framework so developers don't rebuild it for every project.

When an agent acts — calling a tool, hitting an LLM, reading a database — that action should pass through the same kind of stack. Kave is that stack.

```
human request  →  [auth → validate → log]  →  your app
agent action   →  [auth → validate → trace → cost]  →  your tools/models/data
                   └──────── Kave ────────────────┘
```

Kave doesn't run your agents. It doesn't care what framework they use or which model they call. It sits in the middle and makes sure every action is **authorized**, **validated**, **observable**, and **affordable**.

---

## The four modules

Every agent action passes through Kave's intercept pipeline, which runs four modules in order:

**Trace** — records the full action as a structured span: inputs, outputs, latency, model used, decision path. Every run is replayable and searchable.

**Auth** — each agent gets its own identity and a scoped set of permissions. Agents never hold real credentials — Kave proxies every call and enforces what each agent is and isn't allowed to do.

**Validate** — every agent output is checked against a schema before it touches your systems. Bad output triggers a retry, a fallback, or an alert — never silent corruption.

**Cost** — every token is metered and attributed to an agent, a task, and a team. Budgets are enforced in real time. You know what an agent will cost before you build it, and you control what it can spend while it runs.

---

## The core data model

Four concepts cover everything in Kave:

| Concept | What it is |
|---------|-----------|
| `Run` | One agent task from start to finish — has an ID, a budget, and a policy set |
| `Action` | One thing an agent does within a run — LLM call, tool use, memory read |
| `Span` | The trace record of one action — timing, input, output, cost, result |
| `Policy` | What a run is allowed to do — permissions, budget cap, output schema |

A `Run` contains many `Actions`. Each `Action` produces a `Span`. All of it is governed by a `Policy`.

---

## Who it's for

**Developers and freelancers** building agent-powered products for clients — Kave gives you auth, observability, and cost control out of the box, so you ship the business logic, not the plumbing.

**Teams running agents in production** — Kave gives you a single place to see what every agent is doing, what it costs, and what it can access, across every framework and model you use.

**Companies with data sensitivity** — Kave is self-hostable. Your agent traces, credentials, and audit logs never leave your infrastructure.

---

## How agents connect to Kave

Three ways, depending on your setup:

**HTTP proxy** — one environment variable, zero code changes. Point your LLM client's base URL at Kave and every call is automatically intercepted.

```bash
export OPENAI_BASE_URL=https://your.kave.instance/proxy/openai
```

**Go SDK** — idiomatic wrapper around any LLM client. Full control, typed, context-aware.

```go
client := kave.Wrap(openai.NewClient(apiKey), kave.WithTracing(), kave.WithBudget(50.00))
```

**OpenTelemetry** — if you already instrument with OTel, point your exporter at Kave. Nothing else changes.
