# Design: FX — Foreign Exchange Rate Service

**Status:** Locked v1 design. Implements decision #3 in `v1_decisions.md`.

## Goal

A reliable, observable currency-conversion service that supports the v1
currency list (USD + Toman) without polluting accounting. The dashboard
needs live rates; the cost meter needs an authoritative rate at the moment
of recording.

## Non-goals (v1)

- Arbitrary multi-currency. Only `USD` and `TMN` participate in conversion.
  Other currencies may live in the rates table for display but do not
  affect accounting.
- Per-customer FX policies (different reference rates per tenant).
- Historical reconstruction of past months' rates beyond the snapshots
  Kave itself recorded.

## Sources

**Primary:** [Frankfurter](https://api.frankfurter.app) — free, no auth,
ECB-derived. Endpoints used:
- `GET https://api.frankfurter.app/latest?from=USD&to=TMN` — latest cross
  rate.
- `GET https://api.frankfurter.app/latest?from=USD` — full table for the
  dashboard.

**Iranian Toman caveat:** Frankfurter does not list IRR/TMN directly
(it's not an ECB reference rate). Two practical options for v1, in order
of preference:

1. **Provider-supplied rate.** Iranian providers typically publish their
   own per-1K-token Toman price in their config. Kave records the rate
   that came with the price. The FX service is *not* consulted for
   Toman-priced actions when the price is already in Toman.
2. **Static configurable Toman/USD reference.** A `kave.yaml` config key
   `fx.tmn_per_usd` with a sane default (e.g., 60_000). The dashboard
   surfaces a banner "Toman rate is operator-set, last updated YYYY-MM-DD."

The v1 contract is: **if a request or PriceBook entry already carries its
own currency-native price, no FX conversion happens**. FX is consulted only
when reporting cross-currency aggregates (e.g., "show this month's spend
in USD" on a dashboard that mixes USD and Toman charges).

## Refresh policy

Three triggers, all funneled through `core/fx.Service.Refresh(ctx)`:

1. **Startup**: blocking on first call, with a 5s timeout. If the call
   fails, the service starts with an empty cache and logs `level=warn`
   with `event=fx.startup_refresh_failed`. The system is still usable;
   conversions return `ErrNoRate` until the next successful refresh.
2. **Periodic**: a single goroutine ticks every 60s. (This is the **one
   exception** to B2 — declared in the linter allowlist with reason
   "scheduled rate sync, observability not action.") Failures are logged
   at `level=warn`, never panic.
3. **On-demand**: a gRPC `FXService.Refresh(RefreshRequest) RefreshResponse`
   RPC the dashboard can call. Rate-limited to one call per 10s per caller
   identity.

## gRPC surface

Replaces the four `/api/v1/fx/*` HTTP routes:

```proto
package kave.runtime.v1;

service FXService {
  rpc ListCurrencies(ListCurrenciesRequest) returns (ListCurrenciesResponse);
  rpc ListRates(ListRatesRequest) returns (ListRatesResponse);
  rpc Convert(ConvertRequest) returns (ConvertResponse);
  rpc Refresh(RefreshRequest) returns (RefreshResponse);
}

message ConvertRequest {
  kave.common.v1.Amount amount = 1;     // includes currency
  string to_currency = 2;
  // Optional: caller-supplied rate snapshot. If set, server uses it
  // verbatim (still records audit row showing it was caller-supplied).
  RateSnapshot snapshot = 3;
}

message RateSnapshot {
  string base = 1;
  string quote = 2;
  int64 rate_micro = 3;       // rate × 1e6, integer for exactness
  int64 captured_at_unix_ms = 4;
  string source = 5;          // "frankfurter" | "operator" | "request"
}
```

`int64 rate_micro` is the integer representation: 1 USD = 60_000.5 TMN
becomes `60_000_500_000` (rate × 1e6). Avoids float at the conversion
boundary.

## Snapshot semantics

Every accounting record (`BudgetEntry`, `SpanRow`) that involves
cross-currency conversion stores the `RateSnapshot` used. Three sources,
in priority order:

1. **Request-supplied** (`ConvertRequest.snapshot`): caller asserts the
   rate, server trusts it but tags the snapshot `source: "request"`. Used
   when an upstream provider returned a price in Toman and the gateway
   wants Kave to record it without re-converting.
2. **Internal latest** (`fx.Service.Latest(base, quote)`): the most recent
   refreshed rate from Frankfurter or operator config. Tagged `source:
   "frankfurter"` or `source: "operator"`.
3. **Internal historical** (`fx.Service.At(base, quote, ts)`): the rate
   active at a specific past time, useful for reconstruction. Tagged
   `source: "frankfurter"` (only Frankfurter-sourced rates are historical;
   operator rates have no history beyond their last value).

If neither (1) nor (2) is available, conversion returns
`fx.ErrNoRate`; the calling code surfaces it to the user as a 503 or
delays the operation. Accounting is never recorded with a missing rate.

## Storage

Existing `FXRateRecord` and `FXCurrencyRecord` tables stay. Add:

- `FXRateRecord.SourceTag` (`frankfurter | operator | request`).
- `FXRateRecord.RateMicro int64` (replaces any float column; if a float
  column exists today, migrate to int64).

Snapshots embedded in `BudgetEntry` reuse the same `RateSnapshot` shape;
either a foreign key or an embedded JSON blob — pick whichever the existing
`BudgetEntry.PriceSnapshot` uses for consistency.

## Failure modes

| Scenario | Behavior |
|---|---|
| Frankfurter unreachable at startup | Service starts; conversions error until refresh succeeds. |
| Frankfurter returns 5xx on tick | Logged; previous cache stays valid; next tick retries. |
| Operator config has no `tmn_per_usd` and Toman action arrives | Action fails with `fx.no_rate_for_currency`. Document in error: "set `fx.tmn_per_usd` or include rate in request." |
| Rate is older than 24h and Frankfurter is unreachable | Conversions still succeed; emit `level=warn` once per hour with `event=fx.stale_rate`. Dashboard shows "rates are stale" badge. |
